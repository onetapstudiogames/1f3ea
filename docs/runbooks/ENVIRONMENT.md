# Environment map

This is the complete environment-variable map as of 2026-09-01. Runtime values belong in
the hosting provider; database URLs, credentials, and private one-run confirmations must
never be committed, pasted into an issue, or included in command output. Defaults in source
are development fallbacks, not proof of production configuration.

| Name | Owner and use | Required/default | Safe change and refusal behavior |
|---|---|---|---|
| `BASE_RPC_URL` | Application runtime; read-only Base JSON-RPC used for receipt, transfer, and canonical-finality checks. | Optional; defaults to `https://mainnet.base.org`. | Change only to a trusted Base mainnet endpoint. RPC requests time out after four seconds; unavailable or malformed evidence is never treated as paid. |
| `CITY_ORIGIN` | Application runtime; fixed sibling origin for unauthenticated city public-record reads. | Optional; defaults to `https://1f3d9.com`. | Must be one bare HTTPS origin with no path, query, fragment, credentials, or wildcard. Invalid configuration stops module startup. |
| `DATABASE_URL` | Application runtime; Neon/Postgres connection used lazily by database-backed routes. Also accepted by the local bootstrap helper only. | Required for database-backed service work; no default. | Store as a provider secret. Runtime may use the provider's serverless/pooled URL. Guarded release migrations deliberately ignore it and require the target-specific direct URLs below. |
| `FACILITATOR_URL` | Application runtime; x402 verification and settlement service. | Optional; defaults to `https://facilitator.payai.network`. | Change only to the reviewed facilitator origin. Requests have an eight-second deadline, reject redirects, and bound response bytes; an uncertain settle is reconciled with the same proof, never paid again. |
| `HOSTED_MARKET_CIMD_ORIGINS` | Application runtime; JSON array of exact HTTPS origins allowed to supply Client ID Metadata Documents. The ChatGPT origin is always included. | Optional; defaults to `["https://chatgpt.com"]`. | If set, it must be a non-empty JSON array of at most 20 exact origins. Invalid JSON or origins keep hosted sign-in unavailable. |
| `HOSTED_MARKET_OAUTH_CLIENTS` | Application runtime; JSON array of statically approved public OAuth clients with `client_id`, `client_name`, and exact `redirect_uris`. | Optional; defaults to `[]`. | At most 50 clients; client IDs must be unique and redirect URLs exact HTTPS URLs. Unsupported fields or malformed values keep hosted sign-in unavailable. |
| `HOSTED_MARKET_SIGNIN_ENABLED` | Application runtime; enables the hosted OAuth connector only when both identity flags and exact client/origin configuration are also ready. | Optional; disabled unless the value is exactly `true`. | Enable only for the reviewed hosted verification ceremony. A reachable connector is not proof until a real protected `me` read is recorded. |
| `MAINTAINER_ID` | Application runtime; numeric merchant ID allowed the capped opening-stock exception and logged moderation actions. | Optional; defaults to `1`. | Production should retain the reviewed maintainer ID. It is parsed as a number at startup; do not change it merely to recover access or inventory. |
| `MARKET_IDENTITY_RECOVERY_ENABLED` | Application runtime; one half of the private `/join`, `/recovery`, and `/rotate` gate. | Optional; disabled unless exactly `true`. | Enable only after the identity schema and private ceremony pass preview checks. Both identity flags and a valid public origin are required. |
| `MARKET_IDENTITY_ROTATION_ENABLED` | Application runtime; the other half of the private identity-page gate. | Optional; disabled unless exactly `true`. | Keep paired with recovery after the reviewed migration and preview ceremony. A missing or different value keeps all three pages dormant. |
| `NODE_ENV` | Application/platform runtime; `production` marks the process as hosted for payment-custody gating. | Set by the runtime; local tools commonly omit it. | Do not use it to open custody. In production, payments remain closed unless `PAYMENT_CUSTODY_READY=1` is also exact. |
| `PAYMENT_CUSTODY_READY` | Application runtime; explicit release latch for any hosted route that could begin or preserve a paid operation. | Hosted environments require exactly `1`; non-hosted local work defaults ready. | Keep absent during payment-schema rollout and any unsafe state. Absence returns 503 before payment work. Set to `1` only after the migration runner and closed-custody probes pass. |
| `PUBLIC_ORIGIN` | Application runtime; canonical market origin used in public links, OAuth metadata, and world bindings. | General fallback is `https://1f3ea.com`; hosted sign-in additionally requires an explicit value. | Use the exact bare HTTPS deployment origin. Invalid OAuth form keeps hosted sign-in unavailable; changing it also changes bridge and OAuth resource identity. |
| `TREASURY_ADDRESS` | Application runtime; public Base address that receives the market's own listing fee. | Required at startup and locked to `0x3b9d230c9b995fb1a10add2d63ce37437916dcfd`. | It is public, not a signing secret. Missing, malformed, zero, or different values fail startup; never use an environment change to redirect fees. |
| `VERCEL` | Platform runtime; exact value `1` marks a hosted process for the payment-custody latch and permits trusted `x-vercel-forwarded-for` values to key OAuth and identity per-IP rate-limit buckets. | Set by Vercel; local tools should not synthesize it. | Any hosted process still needs `PAYMENT_CUSTODY_READY=1` before paid routes open. Without this exact platform marker, forwarded IP headers are ignored and those requests share the `unknown` rate-limit bucket. |
| `VERCEL_ENV` | Platform runtime; any defined value marks a hosted process for the payment-custody latch. | Set by Vercel (`preview`, `production`, or platform-defined environment). | Do not use it as evidence that a particular commit or migration is live. Verify the deployment commit and public behavior separately. |
| `CI` | Test environment; any non-empty value makes Playwright reject committed focused tests through `forbidOnly`. | Normally set by CI; optional locally. | Use `CI=1` when reproducing the CI E2E guard. It has no application-runtime or deployment effect. |
| `PREVIEW_DATABASE_URL_UNPOOLED` | Guarded release runner; direct non-pooled preview Postgres URL. | Required only for `migrate:preview:*`; no default. | Secret. Must name the separately declared database and exact non-production endpoint and use `sslmode=require` or `verify-full`. The runner refuses pooled, production, mismatched, or incomplete targets before connecting. |
| `PRODUCTION_DATABASE_URL_UNPOOLED` | Guarded release runner; direct non-pooled production Postgres URL. | Required only for `migrate:production:*`; no default. | Secret. Must match separately declared production database and endpoint and require TLS. Never substitute `DATABASE_URL`; the runner refuses it. |
| `CONFIRM_MARKET_PREVIEW_MIGRATION` | Guarded release runner; one-run preview acknowledgement. | Required exact value `APPLY_ADDITIVE_MARKET_SCHEMA_TO_ISOLATED_PREVIEW`. | Set only in the private shell for the intended run, then remove it. It does not select the target; target database and endpoint facts are checked separately. |
| `CONFIRM_MARKET_PRODUCTION_MIGRATION` | Guarded release runner; one-run production acknowledgement. | Required exact value `APPLY_ADDITIVE_MARKET_SCHEMA_TO_PRODUCTION`. | Set only after preview evidence and a provider recovery point exist, in the private production-migration shell, then remove it. It never authorizes an application deploy. |

## Where values live

- Vercel owns hosted application and platform values. GitHub `main` owns application
  code; environment changes are not a substitute for a reviewed pull request.
- A private operator shell owns target-specific migration URLs and confirmations for one
  guarded run. The runner does not print the database URL.
- Local `.env*` and `env.txt` files are ignored by Git. That prevents accidental tracking;
  it does not make plaintext files an approved long-term secret store.
- The market needs only public wallet addresses. Wallet private keys, merchant keys,
  recovery codes, OAuth credentials, and payment proofs are not application configuration.
